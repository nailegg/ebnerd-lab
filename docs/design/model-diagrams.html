후보 모델 구조

EB-NeRD 뉴스 추천을 위한 두 후보 모델과 비교 기준(2024 우승팀 모델)의 구조도입니다. 글로 된 설명은 docs/design/models.md에 있고, 이 페이지는 그 그림입니다. 모든 입력은 AGENTS.md "2. 입력 경계" 안에 있어야 합니다. 그 주의 클릭은 test 파일에 없으므로 학습 목표(loss)로만 쓰고 입력으로는 쓰지 않습니다.

모델 A

공식 768D 기사 벡터를 쓰는 기준 Transformer

기사 메타와 공식 768D 내용 벡터로 기사 표현을 만들고, 후보가 자기 개인 기록(직전 21일 클릭, H21)을 cross-attention으로 읽어 개인화한 뒤, 기간 내 인기 숫자와 합쳐 후보 집합 Transformer로 채점합니다.

쓰는 입력 (경계 안) 경계 밖이라 쓰지 않는 입력 학습하지 않는 고정 입력 학습되는 모듈 (번호는 models.md 1.2절의 모듈 번호)

모듈 요약

  • ①② 기사 표현: category · topic · sentiment 임베딩 + Linear(768→128) 어댑터를 거친 공식 벡터 → add → LayerNorm → 128D. 후보 · 기록 공유.
  • ④ impression 인코더: 시각(sinusoidal 128D) · 기기(임베딩 128D) → Linear(256→128) → I0.
  • ③ 후보 문맥 인코더: e_cand와 문맥 숫자 5개(최신 순위, 10분 노출 수 · 순위, 60분 노출 수 · 순위, 각 sinusoidal 128D) → Linear(768→128) → C0.
  • ⑧–⑩ cross-attention: Q = C0, K · V = H21 토큰, head 4 → P21. gate α21 = sigmoid(Linear([C0, P21])).
  • ⑪ ⑫: 8층 128D head 4 Transformer → Linear → 스칼라 점수.

알려진 위험

  • 768D 벡터는 기사마다 고유해서 어댑터를 거쳐도 "이 기사"를 특정할 수 있습니다. train 주의 기사를 외우고 test 주의 새 기사에 일반화하지 못할 수 있습니다. 모델 B가 이 위험을 구조로 막습니다.
  • 공식 768D 벡터가 어떤 텍스트(본문 포함 여부)로 만들어졌는지 확인되지 않았습니다.
  • 기록 토큰에 클릭 시점 정보가 없어 3주 전 클릭과 어제 클릭이 같은 무게입니다.

모델 B · 제안 (검증 전)

제목 · 부제 임베딩을 관계 경로에만 쓰는 모델

덴마크어 문장 인코더로 만든 제목 · 부제 임베딩을 후보와 개인 기록을 비교하는 cross-attention 안에서만 씁니다. 최종 후보 집합 Transformer에는 그 비교의 결과만 들어갑니다. 결과란 사용자의 과거 클릭 기사들을 attention 가중치로 섞은 벡터 o와, 후보와 얼마나 닮았는지를 나타내는 유사도 숫자입니다. 후보 자신의 텍스트 벡터는 들어가지 않습니다. 기사마다 고유한 벡터가 기사 ID처럼 외워지는 길을 막으려는 설계입니다.

쓰는 입력 (경계 안) 학습하지 않는 고정 입력 학습되는 모듈 일부러 막아 두는 경로

설계 규칙

  • 매칭은 내용으로, 인기는 그 뒤에. Q · K에는 텍스트와 메타로 만든 e만 넣고, 노출 수 · 순위는 후보 토큰 인코더에서 합칩니다.
  • 후보와 기록은 같은 인코더. 같은 공간에 있어야 "의미가 가깝다"는 비교가 성립합니다.
  • 메타는 이어 붙인 뒤 줄이기. 고정된 텍스트 64D와 학습되는 메타 임베딩은 크기와 분포가 달라, concat → Linear → LayerNorm으로 128D를 만듭니다.
  • 기록 쪽 시간은 차원을 맞춰 더하기. 클릭 후 경과 시간과 클릭 수를 log 구간 임베딩(128D)으로 바꿔 e_hist에 더합니다. 대안은 시간을 attention 점수에 더하는 bias. 둘 중 무엇이 나은지는 실험으로 정합니다.
  • 빈 기록용 null 토큰. 21일 클릭이 0인 사용자도 attention이 갈 곳이 있어야 합니다.
  • o 벡터는 넘기고, 후보 벡터는 넘기지 않기. o는 기록 쪽 가중합이라 암기 위험이 작고 숫자만 넘길 때보다 표현력이 큽니다. e_cand와 o ⊙ e_cand는 후보 신원을 실어 나르므로 막습니다.
  • 인코더는 고정. 125,541개 기사를 한 번만 인코딩하고 미세조정하지 않습니다.

모델 A와 다른 점

  • 모델 A는 공식 768D 벡터를 기사 표현에 넣어 후보 토큰에도 그대로 들어갑니다. 모델 B는 텍스트를 후보 토큰에서 뺍니다.
  • 텍스트 출처가 공식 벡터에서 제목 · 부제 문장 임베딩으로 바뀝니다. 어느 인코더를 쓸지는 학습 없는 유사도 AUC(models.md 3절)로 고릅니다.
  • 기록 토큰에 클릭 시점 정보와 null 토큰이 추가됩니다.
  • 모델 A의 후보 문맥 인코더와 gate 융합이 후보 토큰 인코더 하나로 합쳐집니다.

o가 담는 정보

o는 "이 후보와 관련된, 이 사용자의 과거 관심사 요약"입니다. 21일 클릭이 축구 10개 · 정치 5개 · 날씨 2개인 사용자라면, 축구 후보에는 o가 축구 클릭들의 가중 평균에 가까워지고, 아무것과도 맞지 않는 후보에는 attention이 null 토큰으로 가서 "관련 관심사 없음"이 됩니다.

담기를 기대하는 정보어디서 오나유사도 숫자만으로는
어느 관심사와 맞았나attention이 고른 기록 기사들의 내용"얼마나 닮았나"만 알고 "무엇과"는 모름
맞은 클릭의 시점 · 반복V에 더한 시간 · 클릭 수 임베딩어제 세 번 읽은 주제와 3주 전 한 번 본 주제를 구분하기 어려움
맞은 기록의 성격V 안의 category · sentiment"부정적 논조의 사건 기사에 반응해 왔다" 같은 정보가 사라짐
매칭이 한쪽에 몰렸나o의 크기엔트로피 숫자로 일부만 전달
같은 화면 후보끼리의 비교후보마다 생기는 o를 Transformer가 견줌핵심 관심사와 주변 관심사에 닿는 후보를 구분하기 어려움
  • 담기면 안 되는 것: 후보 기사 자체의 신원. 후보는 섞는 비율 wᵢ에만 영향을 줍니다.
  • 남는 위험: 후보와 같은 기사가 21일 기록에 이미 있으면 o가 그 기사 벡터와 거의 같아질 수 있습니다. 그 기록을 attention에서 빼는 방식과 두는 방식을 비교합니다.
  • 확인 방법: o만으로 후보 category를 맞히는 probe는 잘 맞아야 하고, 후보 기사 ID probe는 거의 못 맞혀야 합니다.
