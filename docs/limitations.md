# 받아들인 한계

실 서비스 제약을 엄밀히 흉내 내면 연구가 불가능해지는 지점에서, 의도적으로 느슨하게 둔 것들. 결과 해석 시 함께 읽는다.

## 1. 기사 메타는 최종 snapshot

`articles.parquet`의 제목 · 부제 · 본문 · category · topic · sentiment는 데이터 배포 시점의 값이다. `last_modified_time`이 노출 시각 t 이후인 기사가 있으므로, 엄밀히는 t 시점에 사용자가 본 제목과 다를 수 있다. 수정 전 값은 데이터에 없어 복원할 수 없다. 공식 768D 벡터도 같은 snapshot에서 만들어졌다.

→ 그대로 쓴다. 다만 기사 누적치(`total_inviews`, `total_pageviews`, `total_read_time`)는 7일 전체의 합이라 성격이 다르고(명백한 미래), 쓰지 않는다.

## 2. 집계 지연 없음

실 서비스에서 "t 이전 노출 수" 같은 집계는 수초–수분 지연된다. 여기서는 t보다 이전이면 즉시 쓸 수 있다고 본다.

## 3. 그 주의 클릭 부재

test 파일에는 노출 기간 안의 클릭이 없다. 실 서비스라면 알 수 있는 "t 이전 다른 사용자의 클릭"을 쓸 수 없다. 이것은 느슨한 쪽이 아니라 **엄격한 쪽**의 한계다. 점수판이 hidden test인 동안은 받아들이고, 후속 validation protocol 연구에서 되돌아본다.

## 4. 점수판이 외부 의존

Codabench 2469는 조직자가 직접 돌리는 worker로 채점한다. 2025-07-26 한 차례 멈췄고 08-03 복구됐다. 예고 없이 다시 멈출 수 있으며, 그동안은 hidden 점수를 얻을 수 없다. 로컬 validation 점수와 hidden 점수의 대응점을 쌓아 두는 이유다.
