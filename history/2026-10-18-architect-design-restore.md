# 2026-10-18 Architect — 후보 모델 설계 복원

## 배경

사용자가 Plan을 만들다가, 재구축 전 `docs/plan.md`에 있던 모델 설계(모델 A · B, LightGBM 축소 실행안, 다이어그램 HTML)가 저장소 어디에도 없다는 것을 발견했다. 10-17 재구축 때 Architect가 D4("이전 저장소의 결정과 코드 비승계")에 묶어 함께 지운 것이다. 사본은 `C:\ebnerd-data\archive\repo-2026-10-17\docs\`에 있었다.

Architect의 판단 실수였다. D4는 제약이 되는 결정을 버리자는 것이었는데, 모델 설계는 제약이 아니라 연구 제안이다. 둘을 구분하지 않았다.

## 결정 두 가지

**1. 설계 제안이 사는 층.** `AGENTS.md` "6. 어디에 적는가"의 다섯 층(Rule · Plan · State · History · docs) 어디에도 100줄짜리 설계 제안이 들어갈 자리가 없었다. 원칙이 아니니 Rule이 아니고, 1페이지 Plan에는 길고, 시작 전이라 State가 아니고, 사실이 아니라 제안이니 docs 정의 밖이고, history는 안 읽는다. docs 정의를 "사실, 한계, 그리고 채택 전 설계 제안(`docs/design/`)"으로 넓혔다. 제안의 채택 여부와 시점은 Plan · State가 정한다. 사용자 승인.

**2. 복원 자격.** "확정 설계"가 아니라 **"후보 설계"**로 복원한다. 옛 문서는 EASEM v2 모델 대비 무엇을 뺐는지("정답 경로 3개를 닫은"), test-parity 감사 통과를 전제로 한 실행 순서, feature allowlist 등 지금 저장소에 없는 것을 전제로 쓰여 있었다. 사용자 요구: 옛 맥락 참조를 확실히 걷어내고 부족한 맥락 없이 새로 자세히 설명할 것. 채택 결정은 M3 · M4 시작 시 State에서 내린다.

## 한 일

- `docs/design/models.md` 신규 작성. 0절(문제 · 입력 경계 · 입력 묶음 · 공통 뼈대 · loss)을 새로 써서 문서 혼자 읽히게 했다. 1절 모델 A, 2절 모델 B, 3절 인코더 선택 절차(옛 L2), 4절 우승팀 참고, 5절 입력 경계 대조표(새로 추가), 6절 채택 시 정할 것. 옛 "v0", "v2 대비", "감사 S8 뒤", "allowlist" 참조는 전부 제거. v2 계보는 머리말 한 줄만.
- `docs/design/model-diagrams.html` 재작성. SVG 세 장(모델 A · 모델 B · 우승팀 v1170)은 유지하고 라벨을 고쳤다("✕ 정답 파생" → "✕ test에 없음", "재방문 신호(v2에서 추가)" 블록 삭제 → "경계 안이지만 첫 실험에서 뺀 것"으로 대체, "v0" → "모델 A"). 글 카드는 전부 다시 썼다. "데이터 처리 규칙과 누수 검사"(옛 감사 절차) 카드는 삭제. 비교표는 세 모델로 확장.
- 옛 LightGBM 실행안의 L1(arm C 기준선 1회)은 복원하지 않았다. Plan M3가 LightGBM lambdarank를 이미 다른 역할(첫 모델)로 두고 있어 중복이다. L2(유사도 단독 AUC)만 3절로 살렸고 M3의 유사도 피처 정의로도 쓰이게 연결했다.
- 우승팀 AUC 수치가 옛 문서 두 곳에서 "hidden test AUC"와 "공식 validation AUC"로 다르게 적혀 있었다. 어느 쪽인지 확인하지 못해 "보고된 값, split 확인 필요"로 적었다. `docs/data.md`의 "공식 validation AUC" 표기도 같은 불확실성이 있다.
- `AGENTS.md` docs 정의 한 구절, `PLAN.md` M3 · M4 포인터.
